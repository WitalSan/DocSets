Техническое задание
Постоянные сессии импорта OneNote
Цель

На текущий момент импорт OneNote выполняется как разовая операция с отображением прогресса в диалоговом окне.

После закрытия окна пользователь теряет возможность:

посмотреть результаты импорта;
узнать статистику;
увидеть предупреждения;
продолжить незавершённый импорт.

Необходимо превратить импорт в полноценную сущность DocSets — сессию импорта, которая сохраняется вместе с DocSet, отображается в дереве и может быть продолжена после перезапуска приложения.

Пользовательский сценарий

Пользователь выбирает:

Файл
    Импорт
        OneNote...

После выбора записной книжки:

создаётся новая сессия импорта;
в дереве появляется соответствующий узел;
импорт начинается в фоновом режиме;
страницы появляются в дереве DocSets по мере импорта;
пользователь может продолжать работу с программой.

После завершения результаты импорта остаются доступны независимо от того, было ли закрыто окно прогресса.

Дерево

Добавить специальный системный узел:

Imports
    OneNote - OneNote.Test
    OneNote - SigmaIT

Узел Imports является системным аналогично History, Pins и другим служебным разделам.

Он не содержит пользовательских документов.

Его назначение — хранение сессий импорта.

Сессия импорта

Для отображения в дереве вводится новый тип узла.

Например:

ImportSessionNode

Каждый узел соответствует одной операции импорта.

Например:

Imports

    OneNote - OneNote.Test

    OneNote - SigmaIT

Название формируется как

ТипИмпорта - ИмяИсточника
Контекстное меню

Для узла доступны команды:

Открыть

Продолжить

Остановить

Удалить
Открыть

Открывает страницу результатов импорта.

Продолжить

Доступно если сессия находится на паузе.

В дальнейшем должно также использоваться для обновления импортированной записной книжки.

Обновлять разрешается только страницы, которые:

были изменены в OneNote;
после импорта не изменялись пользователем в DocSets.

Полную синхронизацию пока не реализовывать.

Остановить

По сути является постановкой импорта на паузу.

Импорт должен завершить текущую безопасную операцию и сохранить состояние.

Удалить

Удаляет только информацию о сессии.

Импортированные документы DocSets остаются без изменений.

Представление результатов

Двойной клик по сессии открывает отдельное представление.

Оно открывается аналогично обычной заметке через механизм DocContent.

Само представление необходимо разместить в

DocSets.UI.WinForms

Desktop-проект не должен содержать собственную реализацию данного окна.

Представление должно содержать

Общую информацию:

источник;
дата создания;
время начала;
время окончания;
длительность;
текущий этап;
статус;
общий прогресс.

Статистику:

количество разделов;
количество страниц;
изображений;
вложений;
таблиц;
тегов;
внутренних ссылок;
внешних ссылок;
объектных ссылок.

Информацию о производительности.

Информацию о предупреждениях.

Информацию об ошибках.

Список проблемных объектов.

Должна использоваться и расширяться существующая информация, которая сейчас отображается в диалоговом окне окончания импорта.

Состояние сессии

Для каждой сессии необходимо хранить:

идентификатор;
название;
тип источника;
идентификатор источника;
имя источника;
целевой узел дерева DocSets;
текущий статус;
текущий этап;
время создания;
время запуска;
время окончания.
Состояние страниц

Для каждой импортируемой страницы необходимо хранить:

OneNotePageId

DocSetsNodeId

Status

Дополнительно сохранять:

время импорта;
время изменения страницы OneNote;
контрольную сумму импортированного содержимого.

Это потребуется для будущего механизма обновления.

Кэш разрешения объектных ссылок

Самая дорогая часть импорта — вызовы

GetHyperlinkToObject()

После постановки импорта на паузу либо после завершения приложения уже выполненные COM-запросы не должны повторяться.

Поэтому необходимо сохранять кэш соответствий

PageId + SourceObjectId

↓

HyperlinkObjectId

Сохранять как успешные, так и неуспешные результаты.

После восстановления сессии обратный индекс должен строиться автоматически.

Выполнение импорта

После запуска импорт выполняется в фоне.

По мере завершения страницы она сразу появляется в дереве DocSets.

Не требуется ждать окончания всего импорта.

Контрольные точки

Состояние необходимо сохранять:

после завершения страницы;
после смены этапа;
при постановке на паузу;
во время длительного разрешения объектных ссылок через определённое количество COM-вызовов.
Завершение приложения

Если приложение закрывается во время импорта,

все активные сессии должны автоматически перейти в состояние

Paused

с сохранением текущего состояния.

Если приложение завершилось аварийно,

то при следующем запуске такие сессии должны отображаться как

Interrupted

и предлагать продолжение.

Продолжение импорта

После открытия DocSet необходимо загрузить сохранённые сессии.

Для каждой незавершённой сессии должна быть доступна команда

Продолжить

При продолжении необходимо:

восстановить состояние;
восстановить кэш объектных ссылок;
повторно получить актуальную структуру OneNote;
пропустить уже полностью импортированные страницы;
повторно импортировать страницу, которая была прервана;
продолжить текущий этап.

Импорт не должен создавать дубликаты уже существующих страниц.

Хранение на диске

Для каждого DocSet создать каталог

Imports

Например

MyDocSet.docsets

    Imports

        OneNote_-OneNote.Test.json

        OneNote_-SigmaIT.json

Файл содержит полное состояние сессии.

Включая:

параметры импорта;
состояние страниц;
кэш объектных ссылок;
отчёт;
профиль производительности;
предупреждения;
ошибки;
текущий прогресс.

Запись должна выполняться безопасно через временный файл с последующей атомарной заменой.

Первая версия

В рамках данной задачи реализовать:

постоянные сессии импорта;
отображение их в дереве;
открытие результатов импорта;
выполнение импорта в фоне;
постановку на паузу;
продолжение после перезапуска;
сохранение кэша разрешения объектных ссылок;
сохранение отчёта.

Не реализовывать:

автоматическое обновление импортированной записной книжки;
синхронизацию изменений;
разрешение конфликтов;
универсальную систему фоновых задач.

Эти возможности будут реализованы отдельными задачами.

Требования к реализации

Перед внесением изменений необходимо изучить существующую архитектуру проекта.

Использовать существующие механизмы:

системных узлов дерева;
DocContent;
OneNoteImportService;
отчётов импорта;
профилирования;
сохранения DocSet.

Не создавать параллельных реализаций существующих компонентов.

После завершения:

собрать все затронутые проекты в Release;
устранить ошибки сборки;
сохранить существующую функциональность импорта;
предоставить отчёт о выполненной работе с перечнем изменённых проектов, классов и основных архитектурных решений.

Мне этот вариант нравится значительно больше предыдущего. Он написан не как "промпт для ИИ", а как настоящее техническое задание. Его можно положить в Docs/Architecture/ и через полгода он останется понятным любому разработчику — человеку или Codex.
