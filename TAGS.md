# Система тегов DocSets

Документ описывает систему тегов в её текущем виде: модель данных, пользовательский
интерфейс, правила назначения и фильтрации, хранение, перенос при копировании и
известные ограничения.

## Назначение

Теги — именованные метки, которые можно назначать папкам и заметкам дерева DocSets.
Один узел может иметь несколько тегов, а один тег — использоваться любым количеством
узлов. Теги не образуют иерархию и не влияют на структуру дерева или тип узла.

Каталог тегов принадлежит открытому DocSet. Назначение хранится в самом узле как
список идентификаторов тегов.

## Модель данных

Определение тега представлено классом `TagDefinition`:

```json
{
  "id": "code-review",
  "name": "Code Review",
  "color": "#5BC0DE",
  "icon": "review"
}
```

Поля:

- `id` — устойчивый идентификатор, по которому узлы ссылаются на тег;
- `name` — отображаемое имя;
- `color` — строковое значение цвета, обычно `#RRGGBB`;
- `icon` — ключ встроенной иконки.

Узел `DocumentItem` хранит назначения в `TagIds`:

```json
{
  "id": "services",
  "name": "Services",
  "tagIds": ["todo", "review"]
}
```

При присвоении `TagIds` пустые значения удаляются, а повторяющиеся ID устраняются
без учёта регистра.

## Стандартные теги

Если каталог тегов нового или загруженного DocSet пуст, автоматически добавляются:

| ID | Имя | Цвет | Иконка |
|---|---|---|---|
| `bug` | Bug | `#D9534F` | `bug` |
| `todo` | Todo | `#F0AD4E` | `check` |
| `critical` | Critical | `#C9302C` | `warning` |
| `review` | Review | `#5BC0DE` | `review` |

Стандартные теги добавляются только при полностью пустом каталоге. Если в DocSet уже
есть хотя бы один пользовательский тег, недостающие стандартные теги автоматически
не дополняются.

При загрузке также проверяются ID определений. Пустой или повторяющийся ID заменяется
новым уникальным ID.

## Формирование ID

При создании тега ID строится из имени:

1. Имя переводится в нижний регистр.
2. Последовательности символов, не являющихся буквами или цифрами, заменяются одним
   дефисом.
3. Начальные и конечные дефисы удаляются.
4. Для пустого результата используется `tag`.
5. При конфликте добавляется суффикс `-2`, `-3` и так далее.

Примеры:

```text
Code Review   → code-review
Code/Review 2 → code-review-2
***           → tag
```

Сравнение ID выполняется без учёта регистра. Переименование существующего тега не
изменяет его ID, поэтому назначения узлов остаются действительными.

## Управление тегами

Диалог `Manage tags...` позволяет:

- добавить тег;
- удалить тег;
- изменить имя;
- изменить строку цвета;
- выбрать встроенную иконку.

Доступные ключи иконок:

```text
без иконки, bug, check, warning, review, star, bookmark, idea
```

При добавлении имя обязательно и не может совпадать с именем существующего тега без
учёта регистра. Новый тег из контекстного меню сразу назначается выбранным узлам.

При удалении определение удаляется из каталога, а его ID рекурсивно удаляется из всех
постоянных узлов DocSet. Эта операция не оставляет известных «висячих» назначений.

## Назначение узлам

Назначение выполняется через контекстное меню узла `Tags`.

Поддерживается множественное выделение:

- флажок установлен, если тег назначен всем выбранным узлам;
- промежуточное состояние означает, что тег есть только у части выбранных узлов;
- щелчок при полном назначении удаляет тег у всех выбранных узлов;
- в остальных случаях тег назначается всем выбранным узлам.

Теги можно назначать как обычным заметкам, так и папкам. Локальные виртуальные узлы
не получают собственных назначений. Для Pin и Recent интерфейс разрешает исходный
узел и изменяет его `TagIds`.

Операции добавления, удаления и массового переключения тегов проходят через механизм
мутаций ViewModel, сохраняют DocSet и участвуют в общей истории Undo/Redo. Поля
существующего определения в диалоге редактируются непосредственно; итог сохраняется
при закрытии диалога.

## Отображение

В таблице дерева существует колонка `Теги`. Она показывает:

- до четырёх иконок тегов;
- индикатор `+N`, если тегов больше четырёх;
- текстовый список имён через запятую.

Если определение для сохранённого `tagId` не найдено, в текстовой колонке показывается
сам ID, а вместо неизвестной иконки используется стандартный нейтральный знак.

Поле `color` определения сейчас сохраняется и редактируется, но не используется при
отрисовке тегов, дерева или фильтра. Цвет узла `BookmarkColor` — отдельная система и
с цветом тега не связан.

## Фильтрация дерева

Панель `Теги` над деревом позволяет включить один или несколько тегов.

Текущая логика:

```text
нет выбранных тегов → теговый фильтр отключён
выбран один тег      → узел должен иметь этот тег
выбрано несколько    → узел должен иметь хотя бы один из них (OR)
```

Теговый фильтр объединяется с текстовым фильтром и фильтром цветов узлов по логике
AND. То есть узел должен одновременно пройти каждый активный вид фильтра.

Если дочерний узел соответствует фильтру, его родительские узлы остаются видимыми,
чтобы сохранить путь к результату. Родитель при этом не обязан сам иметь искомый тег.

Выбранные ID тегов фильтра сохраняются в локальном состоянии решения в
`filterTagIds`. Поэтому фильтр относится к пользовательскому интерфейсу конкретного
решения, а не к переносимым данным DocSet. Команда `Без фильтра` очищает только
теговый фильтр.

## Хранение

В каталожном формате DocSets определения находятся в `docsets.json` в массиве
`tags`, а назначения — в поле `tagIds` элементов массива `items`:

```json
{
  "tags": [
    {
      "id": "todo",
      "name": "Todo",
      "color": "#F0AD4E",
      "icon": "check"
    }
  ],
  "items": [
    {
      "id": "task-1",
      "name": "Проверить импорт",
      "tagIds": ["todo"]
    }
  ]
}
```

Пустой список `tagIds` при сохранении элемента опускается. Определения и назначения
восстанавливаются при следующем открытии DocSet.

## Копирование и вставка

При копировании узлов во внутренний JSON-буфер DocSets включаются:

- `TagIds` каждого копируемого узла;
- определения только тех тегов, которые реально используются скопированными узлами.

При вставке отсутствующие определения объединяются с каталогом целевого DocSet по
ID. Если такой ID уже существует, используется существующее определение целевого
DocSet; входящее определение с тем же ID не заменяет его.

Следствие: если в двух DocSet один ID имеет разный смысл или оформление, после вставки
назначение будет связано с определением целевого DocSet.

## Текущие ограничения

- Нет иерархических тегов, групп тегов и синонимов.
- Нет режима фильтрации «узел содержит все выбранные теги» (AND внутри списка тегов).
- Цвет тега не участвует в визуализации.
- Значение цвета не проверяется на корректность формата.
- В менеджере прямое переименование может создать пустое или совпадающее имя;
  проверка уникальности выполняется при создании, но не при последующем редактировании.
- Переименование не меняет ID автоматически.
- Нет отдельной сортировки дерева по тегам.
- Нет счётчика использования тега и предупреждения перед его удалением.
- При объединении буфера определения с совпавшими ID не сравниваются по имени,
  цвету и иконке.

## Основные компоненты реализации

- `DocSets.Model/Model.cs` — `TagDefinition`, `DocumentSetsState.Tags`,
  `DocumentItem.TagIds`, локальный `FilterTagIds`.
- `DocSets.Core/Services/TagService.cs` — стандартные теги, ID, добавление,
  назначение, удаление и объединение определений.
- `DocSets.Core/ViewModels/DocSetsViewModel.cs` — команды и сохранение мутаций.
- `DocSets.Serialization/DocSetDocumentRepository.cs` — чтение и запись каталога и
  назначений.
- `DocSets.UI.WinForms/Forms/DocSetsWinFormsControl.cs` — контекстное меню,
  отображение и фильтрация.
- `DocSets.UI.WinForms/Forms/TagManagerDialog.cs` — редактор каталога тегов.
- `DocSets.UI.WinForms/Icons/TagIconProvider.cs` — встроенные иконки.
- `DocSets.Tests/TagServiceTests.cs` — основные проверки поведения.
